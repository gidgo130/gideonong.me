# Gideon A. Ong — Personal Website

## What this project is
Personal portfolio and career site for Gideon A. Ong, a Mechanical Engineering student at the University of Tulsa in the International Engineering and Language Program (5-year).
Degrees: the full list is on the published transcript. Site copy intentionally names only a subset
(mechanical engineering and Spanish, minoring in math and economics). That's Gideon's choice, so the
degrees don't distract. Don't flag it or "fix" it.
Audience: engineering recruiters and hiring managers.
Domain: gideonong.me. See plan.md for the development roadmap.

## Stack
Plain HTML + CSS + vanilla JavaScript. No frameworks, no build tools, no npm.
External resources: Google Fonts only (Lora + DM Sans), plus GoatCounter's count.js for
analytics (see Analytics below).
api/ holds Vercel serverless functions (since 2026-10-13): Node built-ins + fetch only, no
package.json, no npm, no build step. Vercel compiles their `export` syntax to CommonJS.
/learning is the one exception: it also loads Barlow Semi Condensed, Source Serif 4 and
JetBrains Mono, and its Reflections pages render math with a self-hosted, pinned KaTeX
(learning/assets/vendor/katex/, no CDN; see /learning below).

### Documents (resume / CV / transcript)
- Buttons opt in with data-doc-link="resume" | "cv" | "transcript". js/main.js resolves
  the href from the generated manifest js/docs-data.js (const DOCS): active language →
  the other language → the element's existing href. A type with no file in any language
  gets its buttons hidden (hidden attribute). No network requests, no localStorage.
- To publish a new document: drop a dated PDF into assets/pdfs/<type>/ and commit. The
  pre-commit hook regenerates and stages js/docs-data.js. Filenames must match
    "<en|es> Gideon Ong Resume <YYYYMMDD>.pdf"   (assets/pdfs/resume/)
    "<en|es> Gideon Ong CV <YYYYMMDD>.pdf"       (assets/pdfs/cv/)
    "<en|es> Gideon Ong Transcript <YYYYMMDD>.pdf" (assets/pdfs/transcript/)
  Anything else is ignored with a warning. Transcript PDFs are generated by
  scripts/transcript/ (Python, dev-only, see scripts/transcript/README.md); its .docx
  scratch output (scripts/transcript/output/) is gitignored. To preview before committing:
    node scripts/build-docs-manifest.js
- One-time setup per clone (the hook lives in the repo, but git must be pointed at it):
    git config core.hooksPath .githooks
  If node is not on PATH the hook prints a warning and the commit still goes through;
  run the script by hand afterwards. (The hook's first step, the analytics data/secret guard,
  does block: see Analytics.)
- This is dev-side tooling, not a site build step: the site still deploys as plain
  static files, and js/docs-data.js is committed like any other file.
- Dev files are excluded from deploys by .vercelignore (*.md, LICENSE*, scripts/, .githooks/,
  .gitattributes, references/, staging/, learning/workshop/). Add any new dev-only path there.
- about.html's resume → CV + transcript morph (js/about.js), by what the manifest holds:
  both CV and transcript → resume morphs into CV + Transcript; exactly one → resume morphs
  into Resume + that document (a clone of the resume button fills the top slot); neither →
  no morph, the resume button stays static.
- The public CV is the Professional CV, not the Full CV (Gideon's decision, 2026-09-29).
  assets/pdfs/cv/ holds only the Professional CV (EN/ES), which leaves out political and

### Analytics (2026-09-30)
- Every main-site page's <head> ends with `<script defer src="js/analytics.js">` (`../js/` in
  projects/<slug>.html). A NEW page must include it too; new project shells get it
  automatically because the editor copies projects/g-view.html. /learning does not load it.
- js/analytics.js loads two cookieless tools (no consent banner): Vercel Web Analytics
  (same-origin /_vercel/insights/script.js; exists only on Vercel deploys) and GoatCounter
  (gc.zgo.at/count.js, site code GC_CODE = "gideonong"). Neither loads on the siteData.isDev
  hosts, so Live Server stays console-clean and local previews are never counted.
- GoatCounter click events come from ONE delegated document listener in js/analytics.js — no
  markup attributes, so JS-rendered links are covered: doc-<type>-<lang> (data-doc-link
  buttons), email (mailto:), out-<host> (links to other sites), lang-<en|es> (the toggle).
  Do not add data-goatcounter-click attributes; extend the listener instead.
- "Exclude me" flag (2026-10-13): any page with `?notrack=1` sets localStorage `noTrack` = "1"
  and GoatCounter's own `skipgc` = "t"; `?notrack=0` removes both; any other value changes
  nothing. The param is always stripped (history.replaceState; other params and the #hash stay).
  This runs before the dev-host check, so it works on Live Server. While `noTrack` is set, no
  tool loads and no click listener is attached; any new tracker goes behind the same check.
  Every localStorage access in the file is wrapped in try/catch. Gideon sets it once per
  browser/device.
- Self-built collector (2026-10-13, plan.md Phase 3 A2). It runs alongside the two tools above,
  and GoatCounter stays the reference count. js/analytics.js sends
  `navigator.sendBeacon("/api/hit", JSON)` (text/plain, same-origin) for three events:
  - `pageview` on load
  - `click`, with the same names GoatCounter gets (one sendEvent feeds both)
  - `leave` on every visibilitychange → hidden, with `ms` (visible time so far) and `scroll`
    (max % so far); one page view can send several, and analysis keeps the last
  Client fields on every event:
  - `type`, `path` (normalized: `/`, `/index.html`, `/portfolio` → `/`; `.html` dropped; no
    trailing slash), `ref` (referrer host only), `lang` (site language), `nav`
    (navigator.language), `vw` (bucket `<480` / `480-767` / `768-1023` / `1024-1439` /
    `1440+`), `tz`, `sid` (random per tab, sessionStorage `aSid`), `utm` (utm_source)
  - plus `event` on clicks, and `ms` / `scroll` on leaves
  api/hit.js adds:
  - `t` (ISO UTC)
  - `country` / `region` / `city` (x-vercel-ip-* headers)
  - coarse `browser` / `os` / `device` (family names, no versions). The in-app browsers are
    named first, as LinkedIn / Instagram / Facebook; then Edge, Opera, Samsung, Firefox,
    Chrome, Safari, Other
  - `visitor` = first 16 hex of SHA-256(daily salt + IP + UA), where daily salt =
    HMAC-SHA256(ANALYTICS_SALT_SECRET, UTC date): unique per day, not linkable across days
- Privacy rules (collector): NEVER store or log the IP or the raw User-Agent; they are used in
  memory only, for the hash and the UA families. Fields are allow-listed, type-checked and
  length-capped server-side; unknown fields are dropped. Its log lines carry only the
  function's own error messages.
- Rejects: every response is an empty 204, whether stored or not. Nothing is stored for:
  - a non-POST request
  - an Origin other than https://gideonong.me / www, or (on a preview) that deploy's own
    VERCEL_URL / VERCEL_BRANCH_URL, or (under `vercel dev`) http://localhost
  - a body over 2048 bytes
  - a bot UA, or none (regex list in the file; link-preview bots only by their bot names, so
    in-app browsers like LinkedInApp count)
  - bad JSON, an unknown type, or a click without a valid event name
  - more than 60 events per visitor hash per minute (fixed one-minute window)
- Storage: Upstash Redis via its REST API. `RPUSH <prefix>hits:<UTC YYYY-MM-DD>`, one JSON
  record per event; rate counters live at `<prefix>rl:<visitor>:<minute>` (60 s TTL).
  Production has no prefix and its keys expire after 397 days (~13 months); preview deploys
  use `preview:` and `vercel dev` uses `dev:`, with a 7-day expiry. The prefix comes from
  VERCEL_ENV.
- Env vars (Vercel dashboard, Production + Preview; local copies in the gitignored
  .env.local):
  - UPSTASH_REDIS_REST_URL / UPSTASH_REDIS_REST_TOKEN, falling back to the Marketplace names
    KV_REST_API_URL / KV_REST_API_TOKEN
  - ANALYTICS_SALT_SECRET
  - ANALYTICS_EXPORT_TOKEN (api/export.js; also in Gideon's password manager and Colab Secrets)
  If one is missing, the collector stores nothing and still answers 204 (the Vercel log says
  "hit: missing env vars"); the export answers 404.
  `vercel dev` (CLI 64.2) takes the project's Development environment variables, not the
  hand-written lines of .env.local. So the Development environment carries its own
  ANALYTICS_SALT_SECRET (2026-10-15). It's a separate, non-secret value: dev hashes only label
  dev: test data. The Production / Preview salt stays a Sensitive secret. With it, a plain
  `vercel dev --listen 3000` stores events. After changing a Development variable, re-pull
  with `vercel env pull .env.local`.
- `?collectortest=1` / `0` (dev-only override): sets or clears localStorage `collectorTest`
  and is stripped like notrack. While set, that browser loads ONLY the collector, on any host
  (dev hosts included, noTrack ignored), never Vercel or GoatCounter. Use it with `vercel dev`
  (http://localhost:3000) or a preview deploy. On Live Server there is no /api/hit, so the
  browser logs a 405 per beacon; never leave it set on gideonong.me.
- If /api/hit fails at the network level (Vercel outage, ad blocker), the browser logs its own
  "Failed to load resource" line. That is not a JS error, and the page keeps working.
  Upstash outages never reach the browser: the function still answers 204.
- .vercelignore lists `.env*` and `.vercel/`: a CLI `vercel deploy` uploads from disk, and
  without them .env.local would be published.
- Export (2026-10-15, plan.md Phase 3 A3): `GET /api/export?from=YYYY-MM-DD&to=YYYY-MM-DD` with
  `Authorization: Bearer <ANALYTICS_EXPORT_TOKEN>` returns the stored records as NDJSON, oldest
  day first. Responses:
  - Anything unauthorized gets an empty 404: no or wrong token, any method but GET, the token
    in the query string, the server token missing or shorter than 32 characters.
  - With a valid token: 400 + a short reason for bad dates (both required, real calendar dates,
    from ≤ to, at most 31 days); 413 if the body would pass 4 MB (Vercel caps responses at
    4.5 MB); 502 if Upstash fails; 503 if it isn't configured.
  - The token is compared in constant time: both sides SHA-256'd, then
    crypto.timingSafeEqual, so the length doesn't leak either.
  - No CORS headers ever. Always `Cache-Control: no-store` and `X-Robots-Tag: noindex`. The
    token is never logged.
  - Same prefix rule as hit.js: production exports hits:, a preview preview:, `vercel dev` dev:.
  - Reads each day with LLEN, then LRANGE pages of 1000, four pages per pipeline call.
- Notebook (scripts/analytics/, never deployed but PUBLIC on GitHub; README.md there is the
  manual):
  - analytics.py is the source, with `# %%` markers. make-notebook.py writes analytics.ipynb
    with no outputs and metadata.colab.private_outputs = true. Edit the .py, regenerate, and
    commit both; `--check` reports a stale notebook. Never use Colab's "Save a copy in
    GitHub": it bypasses the hook.
  - The token comes from Colab Secrets, else the env var. It's never printed or saved. With no
    token, the notebook runs on built-in sample data.
  - Any FROM–TO is split into ≤31-day requests, and a 413 is halved and retried.
  - Days are UTC, because the visitor hash is salted per UTC day. Unique visitors exist PER
    DAY only, and charts say so.
  - A session's source is its first pageview's referrer: utm_source wins; no referrer from
    the LinkedIn / Instagram / Facebook in-app browser is "linkedin (app)" etc., otherwise
    "direct"; links from the site itself are "(internal)".
  - Optional GoatCounter CSV: its real header is `2Path,Title,Event,UserAgent,…`, gzipped, and
    the export needs "Individual pageviews" on. Only the daily pageview count is used.
  - Chart colors are dataviz reference slots 1 / 2 (#2a78d6 collector, #eb6834 GoatCounter);
    there are no dual axes.
- Keeping data out of the public repo:
  - .gitignore ignores scripts/analytics/* except its four files, plus *.ndjson, *.jsonl
    and goatcounter*.csv(.gz).
  - .githooks/pre-commit runs scripts/check-staged-data.js first. It checks the STAGED content
    and blocks the commit on:
    - a: data files by name
    - b: GoatCounter's CSV header, even renamed or gzipped
    - c: a collector record (`"visitor"` + 16 hex)
    - d: a notebook under scripts/ with outputs or execution counts
    - e: a token-looking literal (Bearer + 20+ characters, a secret env name = a literal, a
      redis:// URL with a password)
  - Without node, a shell fallback checks a and b by name and header.
  - Docs, comments and examples use placeholders (`<16 hex>`, `<ANALYTICS_EXPORT_TOKEN>`,
    `<token>`), which the rules skip.
  - A genuine false positive: `git commit --no-verify`. After changing a rule, run
    `node scripts/check-staged-data.js --all` to check every tracked file.

## Data conventions
Data files: js/tags-data.js, js/projects-data.js, js/experience-data.js. Read-side
helpers in js/data-helpers.js. Array order never matters — everything sorts by `sortDate`
("YYYY-MM") descending; `pinned: true` lifts a project to the top of the index.

- Listing tiers (`listing` on every project):
    "index"    — in the §3 index, the tag filter, search, and its role's "Projects from
                 this role" list; may be `featured` (max 3). Optional `featuredOrder`

                 on their band and surfaced in the index only under an active filter or

                 exist. Experience entries keep a `visible` boolean.

  points. The dots on --fix (.fix, .fix-curve, .ci-bar-fix, the .sw.fix legend swatch, the
  dotted underline on a .lbl-fix label) are a permanent second cue, so the two fits tell apart
  in grayscale (decided 2026-09-28).
  Red may also mark a miss or a flag (a reading outside a band, a range that misses the
  truth, a readout that fails its check); when it does, the caption says so.

  a non-color cue to the red/grey distinctions: highlighted or missed points (.pt-hi) and

## What NOT to do
(Main site. /learning follows its own rules in the section above.)
- Do not make navbar anything other than white (#FFFFFF) in light mode
  (dark mode overrides --nav-bg to a dark warm background, which is expected)
- Do not hardcode display text in HTML — use data-i18n attributes
- Do not put HTML in translations.js — links come from the js/chips.js phrase table
- Two heading classes, two jobs: `.list-heading` (clamp(1.5rem, 1.2rem + 1.2vw, 2rem)) tops a
  list of entries (home featured, projects §2 / §3); `.section-heading` (15px) labels a small
  panel (About). Do not use one for the other's job.
- Do not store `dates` as a literal string — use the { from, to } shape so it translates
- Do not animate on page load or cause layout shift
- Do not use dark mode toggle
- Do not use fixed pixel widths on containers
- Do not use ALL CAPS section labels or numbered decorators (01, 02, 03)
- Do not put tag pills above the project title
- Do not use rose/--rose on structural elements — it belongs only on "say hello" chip
- Do not add npm packages, build steps, or frameworks without explicit instruction
- Do not make section backgrounds compete visually with project images
