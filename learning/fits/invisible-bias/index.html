The Invisible Bias

Most fitting problems leave fingerprints in the residual plot. This one doesn't. The fitted line comes out wrong, the leftovers look perfectly healthy, and taking more data makes you more confident in the wrong answer.

Think of x as something you read off an instrument (a thermocouple temperature, a displacement sensor, a measured voltage) and y as the response you record. All data here is simulated, so we know the true slope: 2.00.

Reading, not setting. If you set x on a dial and write down the setting, the true value wanders around your setting instead. That is a different kind of error, and it does not bias the slope. This module is about x values you read.

What actually fixes noise in x

Two remedies. One is a different fitting method that allows for error in both x and y (orthogonal distance or Deming regression). The other is a design choice: test over a wider range of x, so the noise is small compared with how much x varies.

Show the Python for this fit 
import numpy as np
from scipy import odr

rng = np.random.default_rng(0)
x_true = rng.uniform(0, 10, 60)
x = x_true + rng.normal(0, 2.0, 60)            # noisy x readings
y = 1 + 2 * x_true + rng.normal(0, 1.0, 60)    # noisy y readings

# Ordinary least squares: assumes x is exact
b_ols, a_ols = np.polyfit(x, y, 1)

# Orthogonal distance regression: allows error in x and y
model = odr.Model(lambda B, x: B[0] + B[1] * x)
data = odr.RealData(x, y, sx=2.0, sy=1.0)      # your best estimates of each sensor's noise
fit = odr.ODR(data, model, beta0=[a_ols, b_ols]).run()

print(f"OLS slope: {b_ols:.2f}   ODR slope: {fit.beta[1]:.2f}   true: 2.00")

What to take away

  1. Noise in y costs precision. Noise in x costs accuracy. An ordinary fit assumes x is exact; when it isn't, the slope is pulled toward zero.
  2. The residual plot cannot catch this. The fit adjusts itself so the leftovers look balanced against x. You find this problem by asking how the data was produced.
  3. More data makes it worse, in a way. The spread shrinks around the wrong answer, and the error bars grow confident while missing the truth.
  4. The cheapest fixes happen before you collect data: randomize run order, log what might drift, read x with a better instrument, and test over a wide range.

Three questions to ask about any fit

Is x really exact?

Compare the x sensor's error with the standard deviation of your x values (about 2.9 for x spread evenly over 0 to 10). If the error is more than about a third of that, expect the slope 10% or more too flat.

What changed during the session?

Temperature, supply voltage, warm-up, wear. If it moves with x, it hides inside your slope.

Does y ever push back on x?

In closed-loop tests a controller sets x based on y, so the two are tangled by design.

The name for all of this: statisticians call it endogeneity, meaning the error in y is related to x. Heteroskedasticity is a different problem (uneven scatter) that does show in the residual plot and leaves the slope unbiased. It has its own module, Uneven scatter.
