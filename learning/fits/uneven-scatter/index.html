Uneven Scatter

Many sensors are rated as a percentage of the reading, so big readings carry big errors. The fitted line survives that. The error bars don't.

When the scatter grows (or shrinks) along the fit, the residual plot fans out. Statisticians call this heteroskedasticity: uneven scatter. Here the sensor's error is a fixed 0.5 units plus a percentage of the reading, like many datasheets state it. All data is simulated from y = 1 + 2x, so the true slope is 2.00.

What about taking the log?

If the error is purely a percentage of the reading and the physics is multiplicative (y = a·xb, or exponential growth or decay), fitting log y makes the scatter even. It also changes what the coefficients mean, and a fixed error part (the 0.5 here) comes back as uneven scatter at small readings. When you know σ for each point, weighting is the more direct fix.

What to take away

  1. A fan in the residual plot means uneven scatter. Check the shape first (Module 2): a curve can look like a fan.
  2. The line is still about right. The error bars aren't: too wide where readings are quiet, too narrow where they're noisy.
  3. If you know each reading's σ, weight by 1/σ². Your datasheet usually tells you. Otherwise, use robust (HC3) standard errors for honest slope ranges.
  4. Pooling two instruments or sessions with different precision creates the same problem. Weight them, or fit them separately.

How to do it

Excel

No weighted fit built in. Multiply each row's x, y and a column of 1s by √w, then use LINEST with no constant.

MATLAB

fitlm(x, y, 'Weights', 1./sigma.^2). Robust errors: hac(x, y, 'type', 'HC', 'weights', 'HC3') in the Econometrics Toolbox. (fitlm's 'RobustOpts' is something else: it downweights outliers.)

Python

statsmodels: sm.WLS(y, X, weights=1/sigma**2). Robust: .fit(cov_type='HC3'). scipy: curve_fit(..., sigma=sigma, absolute_sigma=True).
