# /learning/marginalia — the Marginalia series

Dev manual for Marginalia: side questions that come up while Gideon studies, one page each,
usually with an interactive, practical answer first. Not deployed (`*.md` is in `.vercelignore`).
Hub-wide rules (noindex, unlisted, relative links, viewing settings, series bar, link previews,
feedback, line forms) are in `learning/README.md`; decisions and status are in
`learning/learning-plan.md` → Marginalia. This file is the series' own rules and the "adding an
entry" steps.

## Rules of this series

- **Where content comes from.** An entry starts from a promote brief written in Gideon's private
  notes (never committed here). The brief's "keep out" list is binding: no
  professor names, no course numbers or classroom context ("someone asked in class"), no lecture
  examples or their numbers, no homework, no textbook wording. Re-derive from public sources,
  cite them on the page with working links (DOI, arXiv, publisher, author's free PDF), and
  recompute every number independently: never copy a number from a private write-up. Phrasing
  and analogies from Gideon's own private write-ups MAY be reused (they are his words), as long
  as they carry nothing from the keep-out list (Gideon's call, 2026-10-27). Less essential
  results may be cited instead of derived (also 2026-10-27).
- **Practical first.** Each page opens with the short answer and the rule or recipe an engineer
  can use, then the why. Interactives go wherever they help, not only at the end.
- **Code: Excel in the text, everything else in an "other code" tip** (2026-10-27). The Excel
  function stays inline; MATLAB, Python, R and Julia go in a `<button class="codetip"
  data-tip="ID">other code</button>` chip right after it, with tabs in that order. Every snippet
  is RUN before it goes up (one fixed dataset, all four languages agreeing to the printed
  digits); if a language can't be run here, stop and ask Gideon to run it (Julia was checked on
  his PC; MATLAB-only functions Octave lacks, such as `bootci`, are checked against the
  MathWorks docs and say so in the commit). Name the package and the one-time install in a
  comment (`# pip install scipy`, `install.packages("e1071")`, `] add Distributions`).
- **English only.** Text in the HTML (and in main.js for redrawn readouts), no strings files, no
  learning-i18n.js, no `data-es-ready`, no toggle; strings-common.js loads only as data for the
  feedback widget. Only the hub's Marginalia band is bilingual (hub strings.js: `margTitle`,
  `margIntro`, `margAll`, `margListAria`); entry titles stay English, marked `lang="en"`.
- **One registry**, `learning/assets/marginalia.js`. `subject` groups the index (keep the wording
  identical across entries). Dates formatted from their parts with timeZone UTC.
- **Simulated data only where it is simulated**, with a fixed seed and the true model stated;
  everything else exact. Captions say which.
- **The hub panel copies the theme.** learning.css's `.marg-panel` carries COPIES of this
  series' paper, surface, rule, ink, muted, accent, emph and font tokens (light, dark,
  readability); `scripts/tests/tokens.test.mjs` fails on drift. Change a value here, change the
  copy.
- **Offline app:** excluded (build.ps1 `$Exclude`: `learning/marginalia/*` and the registry). The
  hub never requests the registry when `LEARN_OFFLINE` is set, and hides the band when it is
  missing.

## Design ("ink and red pencil", palette 1, chosen 2026-10-27)

- Every page: `<html data-series="marginalia">`; `marginalia.css` overrides learning.css's token
  NAMES under that selector (light, dark, readability, colorblind) and adds the page pieces.
- Palette, in words (values only in marginalia.css): warm off-white paper, a slightly darker
  surface for figures and boxes, graphite ink, an ink-blue accent (links, the first chart
  series), a red pencil (margin notes, the rule box, "attention", the second series), umber and
  green as third and fourth series. Colorblind mode switches the series to Okabe–Ito.
- Type: Newsreader for text and headings (Google Fonts, optical sizes), DM Mono for figures,
  controls, labels and readouts. Body 18 px (20 px in readability mode).
- Margin notes: `<aside class="mnote"><b class="lab">Label</b>Text</aside>`, placed BEFORE the
  paragraph it annotates. From 1180 px the text column shifts left and notes float into a 15rem
  right margin; below that they are inline asides with a red-pencil rule. Headings and figures
  clear them. Use them for the engineering reading of a result (analogies, practical tips, the
  arithmetic behind a number), never for content the main text needs.
- Rule box (`.rulebox`, red-pencil border): the one formula or recipe a reader should leave
  with. At most one or two per page. Numbered steps: `<ol class="steps">`.
- Charts: `../plot.js` (window.MP.plot), the same mechanism as Reflections (one user unit = one
  CSS pixel, 12–13 px text at every width, strokes and dashes constant on screen), plus log axes
  (`xlog`, `ylog`), horizontal reference lines (`hlines`) and tick-label thinning. Series tokens
  `--s1..--s4`, never `--fit` / `--fix`; at most three line forms per chart (solid, `dash:
  "dashed"`, `dash: "dotted"`), markers for anything else, legends repeating the geometry
  (`.legend span.dash / .dotted / .dot / .ring`). Hand-drawn SVGs (the Markov diagram) scale
  their own text to stay 13 px and redraw on resize.
- Math: the self-hosted KaTeX (learning/assets/vendor/katex/), two delimiter pairs only. Long
  display equations get an `.eq-wide` / `.eq-narrow` pair (narrow below 520 px).
- Footer license line: "Text, figures and code here are CC BY-SA 4.0. Cited works remain their
  authors' and publishers'."

## Adding an entry

1. **Registry**: append to `window.LEARN_MARGINALIA` (`ready: false` until it is done).
2. **Folder** `learning/marginalia/<slug>/`: copy an existing entry's `index.html` head and
   plumbing (noindex, trailing-slash script, viewing-settings snippet, fonts, learning.css,
   KaTeX css if math, `../marginalia.css`, series bar with three crumbs, footer with `.fb-slot`
   and license, scripts in the order: KaTeX + render call, learning.js, `../plot.js`, helpers,
   main.js, `../codetip.js` if the page has code chips, strings-common.js, view-settings.js,
   feedback.js). Eyebrow
   "Marginalia NN · <subject>".
3. **Page**: short answer box, contents, numbered sections, margin notes, sources section with
   working links, "Take it with you" (script + Colab link). Code chips: one `<template id="ID">`
   per chip just before `</main>`, holding `<div data-lang="matlab" data-label="MATLAB"><pre><code>…
   </code></pre><p class="ct-note">optional note</p></div>`, then python / Python, r / R,
   julia / Julia. Escape `<`, `>` and `&` inside the code.
4. **Companion**: `<slug>.py` with `# %%` cells, then
   `python learning/workshop/tools/make-ipynb.py marginalia/<slug> --check`.
5. **Card**: a CARDS entry `marginalia-<slug>` in `learning/workshop/tools/make-og-cards.py`
   (a `chart` function in the Marginalia colors), run it, and point the page's og:image at it.
6. **Ready**: set `ready: true`; the hub band and the index pick it up.
7. **Checks** below.

## Checks

- `node --test "scripts/tests/*.test.mjs"`: the token drift test covers `.marg-panel`;
  `marginalia-math.test.mjs` checks clt-math.js against independent SciPy / mpmath values; the
  feedback test accepts `series: "marginalia"`.
- The browser suites in `learning/workshop/tests/` do NOT cover Marginalia pages yet (open item
  in learning-plan.md). Until they do, check by hand at 375 / 768 / 1280 px, light and dark:
  no console errors, no raw `\(` in the text, chart text readable, no label overlaps, every
  control changes its chart or readout, margin notes beside their paragraphs at 1280 px.
  Code chips: hover previews and locks after 1 s (a locked tip stays when the mouse leaves;
  moving into a preview locks it), click/tap opens locked, tabs switch and the choice carries to
  the next chip, Copy works, Esc and a click or tap outside close it, scrolling on a phone does
  NOT close it, the × stays visible at 375 px. Several tips can be open at once (a locked tip
  never blocks hovering another chip); the newest is on top and Esc closes only the top one.
- `make-ipynb.py marginalia/<slug> --check` for each companion.
- After deploy: one feedback send from an entry (it must file an issue labelled
  `series:marginalia`; run `scripts/feedback-labels.py` once first so the label exists), and the
  cards through LinkedIn Post Inspector.
